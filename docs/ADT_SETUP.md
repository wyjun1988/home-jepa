# ADT 준비 — 사용자 단계 1개 + 이후 자동 파이프라인 (2026-08-09)

## 왜 이 한 단계만 부탁드리는가

Aria Digital Twin 은 Meta 의 연구 라이선스 **클릭스루 동의**가 필요합니다(HF 미러는 랜딩 페이지뿐).
약관 동의·계정 생성은 제가 대신할 수 없는 영역이라 이 단계만 직접 해주셔야 합니다. 5분이면 됩니다.

## 해주실 일

1. https://www.projectaria.com/datasets/adt/ 접속 → **Access The Dataset** (이메일 입력/로그인 + 라이선스 동의)
2. 동의 후 받는 다운로드 링크 파일(보통 `ADT_download_urls.json` 또는 유사 이름)을
   `~/work/home-jepa/data/adt/ADT_download_urls.json` 로 저장
3. 저에게 "ADT 링크 받았어" 라고 알려주시면 이후는 전부 자동입니다

참고: 링크 파일은 서명 URL 이라 유효기간(보통 14일)이 있습니다.

## 이후 제가 진행할 것 (준비 완료 상태)

1. **선별 다운로드** — 전체 3.5TB 가 아니라 **2인(multi-person) 시퀀스의 GT 파일만**:
   `instances.json`(물체 메타/동적 여부), 동적 물체 6DoF 시계열, `2d_bounding_box.csv`
   (**프레임별 어떤 인스턴스가 실제로 보였는지 = 우리의 POS 이벤트, 비전 작업 불필요**),
   `aria_trajectory.csv`(착용자 궤적). VRS 영상·depth·segmentation 은 제외 → 수 GB 수준.
   SDK(projectaria-tools 2.1.0, cp39 x86_64 휠 확인됨)는 필요 시에만 설치.
2. **방 매핑** — 씬(아파트/오피스)당 1회, 바닥 평면에서 방 폴리곤 수동 정의 → 3D 위치 → 방.
3. **변환** — 우리 에피소드 포맷으로: POS(2d bbox 가시성), NEG(착용자 방 체류), GT 타임라인
   (동적 물체 방 변화), 시퀀스 스티칭으로 장기 지평 합성 → 무결성 감사 → 전이 평가
   (`eval_transfer.py` 재사용, HOMER+ 와 같은 표 형식).

## 기대치 관리

ADT 는 시퀀스당 수 분·씬 2개라 "며칠 로그" 평가는 스티칭 인공물이 낀다. 역할은
**실센서 관측 스트림에서의 파이프라인 검증**(모캡 GT 로 채점)이지 대규모 벤치가 아니다.


## ⚠️ 공간 구조 정정 (2026-08-12, 사용자 영상 확인으로 확정)

multiskeleton(2인 파티) 시퀀스는 **거실+다이닝 열린 공간 안에서만** 진행된다 — 변환된 37개
에피소드의 가구 구성에 침대·책상·세면대가 전무하고(소파·식탁·선반·수납장뿐), 관찰자는 4개
"구역"을 두루 다니지만(에피소드당 평균 점유 48%/최다구역) 그 구역들은 **k-means 가 한 공간을
쪼갠 인공 분할**이다.

따라서 ADT 수치의 `moved_room` 은 "**열린 공간의 구역 간 이동**"으로 읽어야 하며, 문/벽을
지나는 진짜 방 전환(완전 가림, 복도)은 ADT 로 검증되지 않는다 — 그건 HOMER+(시뮬 실행) 몫이고
실센서로는 미검증 영역으로 남는다. 다인(multiuser 55개)·단일인(meal/work/clean 등 ~90개)
시퀀스가 침실 등 다른 방을 쓰는지는 미확인(확장 후보).

## multiuser 55세션 편입 (2026-08-12)

multiuser GT(3.6GB) 확인 결과: **기기 1대 + 스켈레톤 2명** — 쌍 시점(ToM)은 없지만 "타인이
옮기는" 동거인 시나리오는 성립. 단 수평 이동범위 중앙값 3.5×3.9m 로 multiskeleton 과 동일하게
**한 방 규모** — 방 전환 검증 불가라는 정정(위 절)은 multiuser 에도 그대로 적용된다.
변환 편입: 37→**92 에피소드, 1,627 질의**(감사 PASS), zero-shot 무붕괴 유지.

## decoration 20세션 편입 (2026-08-12)

사용자 영상 관찰("인테리어 시퀀스는 방에 들어간다, 단 방이 하나") 실측 확인: 수평범위 중앙값
5.0×3.3m(파티 3.5×3.9 대비 확장), **2.5m 이상 장거리 물체 이동 29건(최대 6.9m)** — 유일한
침실을 실제로 드나들며 물건을 옮긴다. 1인 시퀀스라 착용자=이동자(moved 질의 기여는 적음)지만,
**문/완전가림을 동반한 실센서 방 전환 관측**이 처음으로 들어왔다. 방이 하나라 방-신호는 사실상
이진이라는 한계는 유지. 최종 벤치: **112 에피소드 / 1,965 질의** (감사 PASS, zero-shot 0.977).

## ⚠️ moved 층 판정 변경 — 관측모델 아티팩트 (2026-08-13, 사용자 영상 확인이 계기)

사용자가 seq107 양 시점 영상을 직접 시청: **관찰자가 물건을 들었다 놓는 것, 소파로 함께 이동하는
것까지 전부 화면에 보인다** — 즉 이 세션에 '못 본 이동'이 없다. 통제 실험으로 확정:
관측 틱을 5초→1초로 좁혀 재변환하면 seq107(M1292) 의 moved 질의 3→**0개 소멸.**

**정정 (전수 재검 후)**: 위 seq107 결과는 **일반화되지 않았다.** 112 시퀀스 전수를 1초틱으로
재변환하니 moved 총합이 45 → **62 로 오히려 증가**했다(시퀀스별: 89개가 0, 나머지에 1~6개).
seq107(M1292) 만 3→0 이었고 짝(71292)은 0→2 다.

이유: 틱을 좁히면 (a) 관찰자가 실제로 본 짧은 순간이 살아나 어떤 이동은 '관측됨'으로 바뀌지만
(b) 5초 틱이 뭉개던 **짧은 미관측 구간**이 드러나 새 moved 가 생긴다 — 두 효과가 시퀀스마다
다르게 작동한다. 즉 **"ADT moved = 관측모델 아티팩트"는 과잉 일반화**였고, 정확한 서술은:
"관측 해상도에 민감하며(45↔62), 세션에 따라 사라지기도 생기기도 한다. 표본이 45~62 로 작아
어느 쪽이든 **정량 벤치로 쓰기엔 불안정**하다."

**실무 판정은 유지**: ADT 는 stayed 무붕괴 검증 · 실센서 관측물리 · 지각 프론트엔드 재료로 쓰고,
**moved/belief 정량 벤치로는 쓰지 않는다**(사유는 아티팩트가 아니라 표본·안정성).
사용자 영상 확인이 준 교훈은 그대로 유효하다: seq107 파티 영상에는 belief 서사가 없다.

ADT 의 유효 역할(축소 확정): stayed 층 무붕괴 검증 · 실센서 관측물리(FOV/가림/검출 통계) ·
지각 프론트엔드 재료. **moved/belief 벤치로는 사용하지 말 것.** 전수(112ep) 1초틱 재검 결과는
`results/adt_tick1_audit.log`.
