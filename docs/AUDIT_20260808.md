# 데이터 무결성 감사 (2026-08-08)

사용자 지시("데이터가 제일 중요, 무결성 확인")로 수행. 도구: `scripts/audit_dataset.py` —
에피소드당 9종 검사(GT 타임라인 정형성 / POS·SELF 관측의 GT 일치 / 질의 라벨 재계산 일치 /
질의 적격성 / 모델 윈도우 인과성 / JEPA 티처 범위 / anchor·피처 정합 / 분할 격리 / 시드 재생성 결정성).

## 발견 → 수정 (구 데이터셋 270 에피소드 기준)

| 실패 | 건수 | 원인 | 수정 |
|---|---|---|---|
| `B.pos_contradicts_gt` | 6,104 | 이동 발효 시점 관례 충돌: 관측 루프는 "틱 t 에 t 미만 이동만 적용", GT 조회는 "t 이하 포함". 픽업 순간 목격(fetch visit)이 전부 모순 판정 | `gt_room(t)` = **t 미만 이동만 반영**으로 통일 (sim·audit·질의 생성 전부) |
| `D.moved_without_move` | 436 | 같은 관례 문제의 라벨 판: 마지막 목격 틱에 집어간 이동이 mover 윈도우 `(last_t, qt]` 밖 → **moved 인데 mover=None** → moved_by 버킷에서 1.3% 누락 | mover 윈도우를 `[last_t, qt)` 로 |
| `C.selfdrop_room` | 349 | 연쇄 이동(내려놓고 다음 틱 재이동) 시 t+1 조회가 다음 이동을 봄 — 감사 규칙 문제 | SELF 이벤트를 gt_moves 와 (obj,t) 정확 매칭으로 검증 |
| `F.teacher_past_next_sighting` | 797 | **JEPA 티처 누수**: qt 를 가로지르는 긴 POS 런의 t1 이 "다음 목격" 이후까지 뻗어 티처가 추가 미래를 봄 | `_future_window` 에서 `t1 > t1[next_sighting]` 이벤트 제외 |
| `C.orphan_selfpick` | 20 | 실오류 아님 — carry 부착("집었고 이동은 이후") 이벤트. | 감사 규칙 완화: 물체가 실제 있던 방에서 집었는지만 검증 |
| (별도) room_feat 정의 불일치 | — | 부정증거 피처가 POS 만 집계, anchor 는 POS+SELF_DROP → 사용자 자가이동 케이스에서 피처와 앵커가 다른 방을 가리킴. **flat_v3 의 moved_by:user 0.97→0.52 붕괴의 원인** | 피처 집계를 anchor 와 동일 정의로 |

## 재생성 후 최종 상태

train 1000 / val 40 / test 80 재생성 → **감사 PASS** (실패 0).
잔여 경고 1종: `B.run_interior_bridged` ×7 — 동거인이 물건을 들고 갔다가 **3분 내 제자리 반납**한
왕복을 POS 병합(공백 ≤3분)이 다리 놓은 것. 끝점 감지는 정확하며, 관측 요약의 문서화된 의미론으로 유지
(런의 t0·t1 = 실제 감지, 내부 = 보간).

test moved 22.0% (목표 20–40% 유지). 시드 재생성 결정성 확인(바이트 동일).
