## 1. 세계 모델 (시뮬레이터 GT 상태)

- **집**: 방 R개 (기본 4–8, 에피소드마다 샘플). 방 종류 vocabulary(거실/침실/부엌/욕실/현관/베란다/서재…). 생성기 내부적으로 방 인접 그래프(에이전트 이동 경로용) — 상태 공간에는 미노출.
- **존(zone)**: 방마다 2–4개 (관측 모델 전용 내부 좌표. 예: 침실 = {침대 주변, 책상 주변, 옷장 주변}).
- **물체**: M개 (기본 30–80). 클래스별 이동성 prior 차등(SGM 프랙티스: 휴대폰·리모컨·컵 高 / 가전·화분 低). GT 상태 = `(room, zone, concealed)` — 모델 출력은 room 만.
- **에이전트**: 사용자 1 + 동거인 1–3. 각자 루틴 스케줄(기상/식사/작업/청소/외출…) → 활동 스크립트 → 물체 이동 이벤트(pick @방A → 이동 → drop @방B). **사용자 본인도 물체를 옮긴다**(자기 행동은 관측됨). **사용자 외출 = 완전 무관측 구간** — 대표 시나리오("나갔다 왔더니 동생이 노트북을 방으로")가 정확히 이 구간에서 발생.
- **시간**: 초 단위. 시뮬 틱 5s(제안). 에피소드 = 며칠(기본 3일). **에피소드마다 집·물체·주민·루틴 전부 재샘플** — 환경 간 일반화를 데이터 차원에서 강제.
- **리얼리즘 가드**: 루틴이 단조로우면 시간표 암기로 환원됨 → 루틴에 확률적 변형(HOMER+ 방식) + 페르소나 랜덤화 + 활동별 목적지 방 분포에 노이즈. moved 질의 비율이 20–40% 나오도록 이동률 튜닝(§5 성공 판정).

## 2. 관측 모델 (결정 4·7)

사용자 에이전트의 ego 1채널만 관측 소스. 1fps 프레임마다:

- 사용자 상태: (방, 존, 헤딩). FOV 원뿔(기본 90°) 안의 존들이 "스캔됨".
- 물체 o 가 프레임에서 **관측**될 조건: 같은 방 ∧ o.zone ∈ 스캔된 존 ∧ ¬concealed ∧ Bernoulli(p_det). p_det 는 물체 크기·존 거리로 결정(기본 0.7–0.95).
- **가림**: 기하 가림만 — 존 단위 근사(FOV 밖 존 비가시, 거리·크기에 따라 p_det 하향). **은폐(concealed, 닫힌 수납 안)는 v0 제외** — 2026-08-07 사용자 결정. 추후 재도입 시 상태 공간 불변(관측만 차단) 설계 유지.
- **산출 이벤트 스트림** (모델 입력):
  - `POS(t, o, room)` — o 를 room 에서 봄
  - `NEG(t, room, zones_scanned)` — room 의 해당 존들을 스캔했으나 (해당 존 소재 물체들) 안 보임
  - `SELF(t, action)` — 사용자 자신의 pick/drop (관측됨)
- FOV 모사의 학습적 의미: **부정 증거가 불완전**해진다("안 보였다 ≠ 그 방에 없다"). 방 입장=전부 관측 모델이면 부정 증거가 확정적이라 문제가 쉬워지고 비현실적.
- 관측 노이즈(오검출·오인식): P1 은 0, P2+ 에서 파라미터화(지각 프론트엔드 대비).
- 1fps 원시 스트림은 이벤트로 압축 저장(동일 관측 연속 구간은 [t_start, t_end] 로).

## 3. 데이터 포맷

에피소드 디렉터리:
- `home.json` — 방/존/물체(클래스·크기·이동성)/에이전트·루틴 시드
- `events.jsonl` — 사용자 관점 관측 이벤트 (POS/NEG/SELF, 위 스키마)
- `gt_timeline.jsonl` — 전체 상태 변화 (물체별 (t, room, zone, concealed, mover))
- `queries.jsonl` — (o, t, gt_room, 층화 태그: moved/stayed, Δt 구간, concealed 여부, mover)

분할: **집 단위** (train 집 ≠ val 집 ≠ test 집). 규모 목표: train 집 수백–수천 (그래프 레벨이라 생성 비용 무시 가능).

## 4. 태스크·지표

- **질의**: t 시점에 비가시(현 프레임에 없음)인 물체 o → P(room) (R-way 분포).
- **층화 리포트**(전부 필수): moved vs stayed(사용자의 마지막 관측 기준) × Δt 구간(분/시간/반나절+) × concealed 여부.
- **지표**: top-1 정확도, NLL·Brier(분포 채점), **기대 탐색 방 수**(예측 분포 순으로 방을 뒤질 때 — 제품 지표: "몇 군데 뒤져야 찾나"), 소실 후 Δt 곡선(OSNOM 식).
- **헤드라인 클레임**: moved 서브셋에서 last-seen 대비 유의미 우위 + stayed 서브셋 무손실(칼리브레이션 확인).
- 제품화 관점 메모(결정 5): 지표가 곧 UX("찾을 확률", "탐색 비용")로 읽히게 유지. 온디바이스/지연 이슈는 P4 이후.

## 5. 모델 (A/B 동시 — 결정 3)

**공통 하네스 먼저**: 이벤트 로그 → 토큰 시퀀스 (object emb + room emb + 이벤트 타입 + TGAT 식 함수형 시간 인코딩 + Δt) 로더, 평가 파이프라인, 질의 배치.

- **공통 백본 v0**: 이벤트 시퀀스 트랜스포머 (방 수준에서는 그래프 구조가 얇아서 이벤트 시퀀스 인코딩이 자연스러움. stock `TemporalSequenceEncoder` 패턴 재활용). 물체—방 이분 그래프 message passing 은 v1 옵션.
- **Track S (supervised)**: 백본 + 질의 토큰 (o, t_now) cross-attention + 방 softmax, CE 학습.
- **Track J (JEPA)**: stock 코어 이식 —
  - context 인코더 = 백본(관측 로그만).
  - target 인코더 = EMA, **특권 정보**(시뮬 full state at t; 실데이터 단계에선 미래 재관측 포함 로그 = 지연 라벨) → 물체별 타깃 latent.
  - predictor = 질의 토큰 (o, Δt) 조건 cross-attention, **롤아웃 없이 Δt 직접 조건**.
  - 마스킹 = 자연 미관측(진짜 결손) + `node_block` 식 추가 마스킹.
  - 붕괴 방지 = EMA + VICReg(분산·공분산, stock `_latent_regularizers` 이식) + imputation anchor(stock `imputation_standalone` 의미론).
  - 2-stage: latent 사전학습 → 인코더 동결 → 방 probe(선형/얕은 MLP).
- **비학습 베이스라인**: last-seen / 빈도 prior(클래스×방) / 시간감쇠 persistence(Toris&Chernova) / Markov 방 전이. (+P2 옵션: LLM-with-log)
- A/B 공정성: 두 트랙 같은 백본 용량·같은 데이터·같은 하네스. 차이는 학습 목적함수뿐.
- 하드웨어: 이 규모(수백만~수천만 파라미터)는 로컬 MPS fp32 로 충분. 스윕만 RunPod/4090.

## 9. v1 — receptacle 재도입 (2026-08-09, P4-2 발견 1 근거로 사용자 승인)

HOMER+ 실측: 실루틴 이동은 가구:방 ≈13:1 — 방 수준 상태공간은 실가정 동역학의 ~92%를 뭉갠다.
v0 결정 2("방 수준")를 개정한다.

- **상태 공간**: location = **receptacle**(가구 표면) id. 방은 receptacle 의 소속으로 유도.
  집당 receptacle 8–30개(방마다 2–5개 + 항상 `floor`). 은폐(닫힌 수납 내부)는 **여전히 제외** —
  receptacle 은 표면(ON) 의미론만.
- **존 통합**: 기존 존 좌표를 receptacle 위치가 대체. FOV 가시성·거리감쇠 코드 동일, 대상만
  receptacle. 물체는 항상 어떤 receptacle 위에 있다.
- **동역학**: 활동이 대상 receptacle 을 지정(work→desk, tv→sofa/coffee_table, meal→dining_table…).
  사용 종료 시 ① 지정석 복귀 p_home ② 활동 receptacle 에 방치 ③ **같은 방 다른 receptacle 로
  이동 p_shift**(설거지→싱크대 등; HOMER 가 보여준 방내 churn 의 원천).
- **이벤트**: POS 에 `recept` 필드 추가, NEG 는 스캔된 receptacle 집합 기준 coverage.
- **질의/층화**: moved 를 3분할 — `moved_room`(방 변경) / `moved_within`(같은 방, 다른 receptacle)
  / stayed. 지표는 receptacle top-1/2 + **방 롤업 top-1**(v0 과 하위호환 비교).
- **모델**: location 슬롯 = receptacle (MAX_RECEPT=32), 임베딩 = recept 타입 + 소속 방 슬롯 +
  인덱스. anchor·부정증거 피처를 receptacle granularity 로.
- **전이**: HOMER+ 를 가구 수준으로 재변환(furniture 노드 1:1 매핑) — 하루 60건 이동의 부유한
  전이 벤치로 격상.
- 코드 스냅샷: `snapshots/pre_receptacle_20260809/`.

## 7. P1 산출물 정의 (스펙 승인 시 착수)

1. 생성기 v0 (`homejepa/gen/`) — config 기반, 시드 재현성.
2. 데이터 검증 리포트 — moved 비율, Δt 분포, 이동 원인 분해, 관측 커버리지 (튜닝 근거).
3. 평가 하네스 + 비학습 베이스라인 4종 결과표.
4. Track S v0 학습·평가.
5. **P1 성공 판정**: (i) moved 비율 목표 범위 달성, (ii) 베이스라인 간 유의미 갭(문제가 자명하지도 불능하지도 않음), (iii) supervised 가 moved 서브셋에서 last-seen 을 이김. 셋 중 하나라도 실패하면 생성기/태스크 재설계 후 재논의.

P2 = Track J 이식 + A/B. P3 = ADT 스티칭 평가(방 수준 매핑) + HOMER+/DynamicTHOR held-out. P4 = 지각 프론트엔드.

## 8. P2 진행 중 확정된 설계 변경 (2026-08-08)

1. **이벤트 윈도우** — 최근 N개 자르기는 질의의 14%(dt>6h는 27%)에서 마지막 목격을
   잘라냈다. 질의 물체 관련 이벤트에 슬롯을 예약(`own_budget=64`)하고 나머지를 최근
   이벤트로 채운다. 같은 256 예산으로 커버리지 100%, 윈도우 시간범위 14.6h→33h.
2. **어트리뷰트 직접 입력** — `anchor`(마지막 증거 방: POS 또는 SELF_DROP)와 Δt 를
   이벤트 윈도우와 별개로 질의 토큰에 준다. 윈도우 잘림과 무관하게 앵커가 보장된다.
3. **2-헤드 readout** — `P(방) = (1-g)·onehot(anchor) + g·softmax_{방≠anchor}`.
   부작용: 방 헤드가 moved 질의(23%)로만 그래디언트를 받아 데이터 기아 →
   **보조 flat softmax 태스크**(공유 트렁크, w=0.5)로 보완.
4. **존 타임라인** — 관측 모델이 시점 t 의 존이 아니라 에피소드 최종 존을 읽던 버그
   수정(`zone_tl` 별도 기록 후 phase 2 에서 replay).
5. **Track J 타깃 정의** — 타깃 인코더는 **질의 물체의 다음 목격까지**의 로그를 본다.
   실데이터에 GT 가 없어도 재관측은 반드시 일어나므로 그대로 이식된다. stage 1 에
   정답 라벨은 들어가지 않는다. imputation 앵커 = 관측 로그로부터 계산한 방별
   체류시간 히스토그램 복원(입력만으로 계산 → 누수 없음).
6. **데이터 규모** — train 240→1000집(질의 12만). 240집에서는 2000스텝에 과적합.

## 11. v4 — 지각 리얼리즘 개정: re-id 제거 + 공가시성 부재판정 (2026-08-09 사용자 지시)

### 11.1 re-id 제거 ("noid" 모드)

문제: 현재 모델 입력의 모든 이벤트에 전역 인스턴스 id(cidx/owner)가 붙어, "다른 방에서 나타난
노트북 = 아까 그 노트북"이라는 **연관(association)이 공짜**다. 실제 1fps 안경에서 트랙 간 재식별은
어렵고, 이 연관 추론이야말로 모델이 배워야 할 능력이다.

- **트랙 단위 동일성만 유지**: 연속 목격(POS 런) 내부의 동일성은 유지(시야 내 추적은 쉬움),
  런 사이의 대응은 제거 — 모델은 "클래스 c 가 표면 R1 에서 [t0,t1] 목격", 나중에 "클래스 c 가
  R2 에서 목격"만 본다. 같은 인스턴스인지는 동역학 정합(소멸+출현+시간)으로 추론해야 한다.
- **질의 재정의**: (물체 id, t) → **(참조 트랙, t)** — "오늘 아침 책상에서 본 그 노트북, 지금 어디?"
  GT 는 그 트랙의 실제 인스턴스(시뮬만 앎)의 현재 위치. 지표·층화 불변.
- **id 누수 제거 목록**: ① 이벤트 토큰의 cidx/owner 제거 ② own-object 마커(sca[:,6])를
  '참조 트랙 토큰 1개' 마커로 교체(현재는 GT id 로 같은 물체 이벤트 전부 마킹 — 누수)
  ③ anchor = 참조 트랙의 (표면, t1) 로 재정의(이후 동클래스 목격과의 연결은 모델 몫)
  ④ 윈도우 예약을 물체 id → 동클래스 이벤트 기준으로 ⑤ loc_feat 의 '이 물체를 이 표면에서
  마지막으로 본 시각' → '클래스 c 를 본 시각' ⑥ 베이스라인도 같은 정보 식단으로(공정성).
- **티처(JEPA)**: 시뮬 학습에선 특권 id 유지(GT). 실데이터 적응 시 티처도 클래스 수준 재관측이
  되어 유사라벨이 노이즈해짐 — 별도 측정 항목.
- **닫힌 세계 유지**: 신규 물체 유입/소멸은 이번에 제외(사용자 지시).
- 구현 노트: **id 제거는 같은 에피소드 파일 위의 로더 뷰** — 데이터 재생성 불필요, EpTensors
  noid=True 플래그. id vs noid A/B 가 같은 데이터에서 성립.
- 신규 층화: **단일 인스턴스 클래스 vs 다중 인스턴스 클래스** 질의 — 연관 능력을 분리 측정.

### 11.2 공가시성 기반 부재 판정 강화

문제: 현재 NEG 는 방 수준 스캔 커버리지라, "그 표면을 제대로 봤고 옆 물건들은 다 인식됐는데
노트북만 없더라"는 결정적 부재 증거가 뭉개진다.

- **표면 수준 NEG**: (표면, 구간, well-seen 플래그) 이벤트 신설 — 근거리·충분 체류로 관측 기회가
  높았던 표면을 명시. (물체별 '없음' 이벤트가 아니라 표면별 '잘 봤음' — 부재는 여전히 모델이
  [잘 본 표면 + 동클래스 POS 없음 + 공존 물체들은 POS] 로 추론; p_det<1 소프트성 유지)
- **공존 증인 피처**: 참조 트랙 표면에 대해 '마지막 well-seen 시각'과 '그때 그 표면에서 인식된
  다른 물체 수(증인 수)' 를 loc_feat 에 추가.
- 시뮬 관측 페이즈 수정 + 재생성 필요(v4 데이터). ADT 변환도 동일 스키마로(2d bbox 로 well-seen
  판정 가능 — 실센서에서 그대로 성립).

### 11.3 함께 갈 것 (우선순위)

1. noid 로더 + 참조트랙 질의 + 베이스라인 식단 통일 (재생성 불필요 — 즉시)
2. 표면 NEG + 증인 피처 (v4 재생성)
3. id vs noid A/B 재학습 + 단일/다중 인스턴스 층화
4. 클래스 오인식 노이즈(컵↔물병) 주입 — noid 세계의 자연스러운 다음 축
5. (기존 유지) 재관측 유사라벨 readout 적응 · nmove 비선형 헤드 · 주단위 실로그 확보

### 11.4 3D/메트릭 정보에 대한 입장 (2026-08-09 사용자 우려 반영, 코드 검증 완료)

**모델 입력에는 좌표가 이미 없다** (검증: make_batch 소비 텐서 = 이벤트타입/클래스/표면·방 슬롯
/시간 피처/coverage — 전부 심볼릭. `e_pos` 는 시퀀스 순서 임베딩이지 공간이 아님).
메트릭 정보의 실제 소재와 처분:

| 소재 | 성격 | 처분 |
|---|---|---|
| 시뮬 FOV 기하(표면 위치·거리 p_det) | 세계를 굴리는 물리 — 시스템 능력 가정 아님 | 유지 |
| 에피소드 JSON 의 recepts.pos | 디버그/감사용, 모델 비노출 | 유지(비노출 명시) |
| ADT GT 라벨(모캡 최근접-가구 귀속) | 평가 라벨 = 특권 정보 | 유지(합법) |
| ADT 관측 스트림 | **3D 불사용 확인** — 가시성은 2d bbox, 관찰자 방 판정은 '보이는 가구 다수결' | 이미 드리프트-무관 |

남는 실제 가정은 "지금 보는 표면이 '그 책상'"이라는 **정적 랜드마크(가구) 인식**이며, 이는
드리프트 나는 메트릭 SLAM 이 아니라 장소 인식 문제 — 시간 단위 드리프트 우려의 대상이 아님.
그 현실적 실패 모드는 **표면/방 오인식**이고, v4 노이즈 축(§11.3-4)에 클래스 오인식과 함께
"표면 오인식(유사 표면 간 혼동)" 으로 편입한다.

### 11.5 장소 = 물체 조합 (co-occurrence context) — §11.4 의 랜드마크 가정 대체 (2026-08-09 사용자 설계)

"표면 인식이 주어진다"는 마지막 가정을 제거한다. 장소의 정체성은 **함께 관찰되는 조합**
(노트북·책상·모니터·키보드)에서 창발하고, 부재는 "조합의 나머지는 보이는데 대상만 반복적으로
결측"으로 판정한다.

1. **관측 = glance 집합**: 짧은 창(수 초)마다 {가구류 검출 + 물체류 검출}의 집합. 인스턴스 id 없음
   (§11.1), 표면/방 심볼 없음. 가구도 검출 대상(책상은 매우 잘 보인다) — 시뮬 FOV 는 표면 가시성을
   이미 계산 중이라 방출만 추가하면 되고, **ADT 는 2d bbox 에 가구가 이미 들어 있어 실센서에서
   공짜로 성립**.
2. **문맥 클러스터링(시스템측, 결정적)**: 로그만으로 공관측 그래프(같은 glance 에 등장 = 엣지,
   체류 높은 가구·준정적 물체가 앵커)를 온라인 클러스터링 → cluster id + **시그니처**(그 문맥에서
   자주 보인 클래스 히스토그램). GT 불사용, 감사 가능.
3. **모델 입력**: 이벤트 토큰의 표면/방 타입 임베딩 제거 → cluster id + 시그니처 피처.
   질의 = 참조 트랙(클래스, 그 트랙의 cluster, 시각).
4. **출력 = cluster 슬롯**: 슬롯 임베딩을 (주어진 타입이 아니라) 시그니처에서 구성. 채점은
   GT 표면→cluster 다수결 매핑(특권, 평가 전용). 방 롤업도 매핑으로만.
5. **부재 판정(사용자 정의 그대로)**: 참조 cluster 의 공존 멤버들이 최근 glance 에서 관찰됐는데
   대상 클래스만 반복 결측 → 강한 제거 증거. witness 피처 = (최근 well-seen 시각, 그때 보인
   공존 멤버 수, 대상 결측 연속 횟수).
6. **검증 게이트(선행)**: 클러스터 순도 진단 — 발견된 cluster 와 GT 표면의 정렬(purity/ARI)을
   시뮬·ADT 에서 측정. 순도가 낮으면 그 자체가 "지각 한계에서의 과제 정의"이며, 채점 granularity
   가 cluster 인 것이 오히려 정직하다.

단계: **A** 데이터측(가구 검출 방출 + glance 화 + 클러스터링 + 순도 진단) → **B** 모델측
(cluster 축 입력/출력 + noid 통합) → **C** id/심볼릭 vs 조합-창발 A/B 재학습 → **D** 오인식 노이즈.

### 11.6 §11.5 축소 확정 — 조합 신호는 어트리뷰트로 (2026-08-09 사용자)

클러스터 축 전면 개편(§11.5 B)은 보류. glance(§11.5-1, 구현됨)에서 **위치 슬롯별 조합 어트리뷰트
4종**을 증류해 loc_feat 에 추가한다 (전부 id-free, 클래스 수준):

| 컬럼 | 의미 | 사용자 시나리오 대응 |
|---|---|---|
| f_seen | 이 위치 타입의 조합이 마지막으로 '증인과 함께' 잘 보인 후 경과 | "그 조합이 자주 관찰되는데" |
| f_wit | 그때의 증인 수(대상 클래스 제외 공존 검출 수) | 옆 물건들은 다 보였다 |
| f_miss | 증인 있는 glance 에서 대상 클래스가 연속 결측된 횟수 | "노트북만 관측 안 되면" |
| f_aff | 과거 대상 클래스가 보인 glance 중 이 위치 타입이 공존한 비율 | 노트북↔책상 조합 친화도 |

동타입 표면(선반 2개)은 어트리뷰트가 공유됨 — 지각 현실의 열화로 수용. glances 의 gt_place 는
순도 진단 전용(특권) — 모델 금지. aug(접미사 절단)와 glance 의 상호작용은 v0 근사로 미적용(명시).
