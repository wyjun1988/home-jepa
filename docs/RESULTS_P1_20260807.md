## 데이터셋 v0

240/40/80 집 (train/val/test), 집 단위 분할, 각 3일, 집당 120질의 → 28.8k/4.8k/9.6k 질의. 생성 ~25s/80집, 총 47MB.
- 방 6–8, 물체 35–49, 동거인 1–3, 사용자 관점 이벤트 ~1,300/에피소드 (POS 1,200 / NEG 129 / SELF 136).
- GT 이동 69회/집/일, 물체의 98%가 최소 1회 관측됨.
- moved 비율은 Δt 에 따라 단조 증가: <10m 7.5% → 10-60m 11.9% → 1-6h 18.5% → >6h 31.8%. **시간이 지날수록 last-seen 이 틀린다**는 태스크의 핵심 성질이 데이터에 들어있음.
- 이동 주체: 동거인 81% / 사용자 19%.

## 베이스라인 공정성 수정 (중요)

최초 `last_seen` 은 POS 이벤트만 "목격"으로 셌다. 그러나 사용자가 **자기 손으로 물건을 내려놓은**(`SELF_DROP`) 경우 실제 시스템은 당연히 그 위치를 안다. 이걸 무시하면 `moved_by:user` 카테고리(19%)에서 베이스라인이 부당하게 0점을 받고 모델이 과대평가된다.

→ `last_known` 베이스라인 추가(POS + SELF_DROP), `persistence`/`markov` 도 SELF_DROP 기준으로 Δt 재계산. **이 수정 하나로 전체 top-1 에서 persistence 가 supervised 를 앞지른다**(0.811 vs 0.777). 수정 전이었다면 잘못된 승리 선언을 할 뻔했다.

## 해석

**1. 진짜 어려운 케이스에서 학습이 이긴다.** `moved_by:housemate`(동거인이 옮김, n=1744)는 관측 로그에 단서가 간접적으로만 남는 우리 태스크의 본질이다. 여기서 supervised 0.290 vs 최고 베이스라인 0.114(hist_freq) — **2.5배**. 탐색 비용으로는 3.25방 → 2.69방. 방이 6–8개니 무작위(≈0.15)보다 확실히 위이고, 이 격차가 P1의 핵심 성과다.

**2. 그런데 전체 지표에서는 진다.** stayed(76%)에서 0.889 vs 0.995 로 잃는 양이 moved 에서 버는 양보다 크다. 모델이 **이동을 과다 예측**한다 — 확률 질량을 퍼뜨려 헤지하는 전형적 miscalibration. NLL 로 봐도 stayed 0.35 vs persistence 0.15.

**3. 결정적 단서: `moved_by:user` 에서 0.949.** 이건 `SELF_DROP` 토큰만 읽으면 1.000 이 나오는 자명한 케이스인데(last_known 이 정확히 1.000) 모델이 못 맞힌다. 즉 v0 는 구조적으로 쉬운 신호조차 완전히 활용하지 못하고 있다. 용량 부족이 아니라(0.65M 파라미터로 충분) **구조를 태우지 않은 탓**으로 본다.

**4. 과적합.** best val 이 step 2000(NLL 0.800)이고 이후 6000까지 1.09 로 악화. best 체크포인트 선택 덕에 test NLL 0.762 로 착지. 다음 런은 2500스텝이면 충분.

## P2 로 넘길 것

1. **2-헤드 분해** — `P(moved) 게이트 × P(room | moved)` 로 나누고, stay 분기는 `last_known` one-hot 에 고정. 태스크의 구조를 모델에 직접 주는 것으로, stayed≈1.0 을 회복하면서 moved 이득을 유지할 수 있다. **P2 최우선.**
2. Track J (JEPA) 이식 후 동일 하네스에서 A/B. 위 2-헤드는 두 트랙 공통 readout 으로 적용해 비교 공정성 유지.
3. 학습 스크립트에 주기적 체크포인트 저장 추가(현재 종료 시에만 저장 — 6천 스텝 날릴 위험).
4. 데이터 확장: 240집은 과적합이 빠르다. 생성이 초당 3집이므로 1000집+ 로 늘리는 비용은 무시 가능.
5. (선택) LLM-with-log 대조군 — 이벤트 로그를 텍스트로 주고 질의. 제품 관점 상한 추정용.
